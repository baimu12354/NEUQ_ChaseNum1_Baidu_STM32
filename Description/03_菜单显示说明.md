# 菜单显示说明

## 1. 模块定位

菜单显示代码主要位于：

- `Code/ChaseNum1_Menu.c`
- `Code/ChaseNum1_Menu.h`
- `Code/ChaseNum1_TFT.c`
- `Code/ChaseNum1_TFT.h`
- `USER/main.c`

当前菜单不是传统交互菜单，而是运行状态诊断页。它的作用是：

1. 显示 MCU 主循环是否还在运行。
2. 显示 NANO 协议收发是否正常。
3. 显示系统、底盘、机械臂、气泵状态。
4. 显示串口硬件错误和协议解析错误，便于定位偶发卡死、丢包或串口异常。

## 2. 初始化和刷新入口

### 2.1 初始化

`USER/main.c` 中调用：

```c
Menu_init();
```

`Menu_init()` 内部会：

1. 初始化 TFT180 屏幕。
2. 设置黑底、文字颜色。
3. 清空动态值缓存。
4. 一次性绘制固定标签，比如 `System`、`Chassis`、`UART2 RX` 等。

固定标签只在初始化时画一次，后续刷新只更新变化的值，避免整屏闪烁。

### 2.2 刷新

`USER/main.c` 主循环里通过 `PrintFlag` 节拍调用：

```c
Menu_poll();
```

`PrintFlag` 在 `CN_PIT2_CALLBACK()` 中每 100ms 置位一次。但 `Menu_poll()` 内部还有自己的刷新限速：

```c
#define MENU_REFRESH_MS 300U
```

因此屏幕实际约 300ms 更新一次。

## 3. 防闪烁机制

菜单显示使用了动态值缓存：

```c
static char g_menu_value_cache[MENU_VALUE_CACHE_LINES][MENU_LINE_CHARS];
static uint16_t g_menu_color_cache[MENU_VALUE_CACHE_LINES];
```

更新函数：

```c
static void Menu_Update_Value(uint8_t line, uint8_t col, uint16_t color, const char *fmt, ...);
```

每次刷新时，它会先格式化新字符串，再和缓存比较：

- 如果内容没变，颜色也没变，不写屏幕。
- 如果内容或颜色变化，只重绘该行的动态值区域。

这样固定文字不会反复擦写，屏幕不会因为整屏刷新而明显闪烁。

## 4. 屏幕布局

当前屏幕横屏使用 160x128 分辨率，6x8 字体约可显示 16 行。

`Menu_init()` 固定标签如下：

| 行号 | 标签 | 含义 |
| --- | --- | --- |
| 0 | `ChaseNum1 Status` | 状态页标题 |
| 1 | `Alive :` | 主循环存活计数 |
| 3 | `System :` | 系统状态 |
| 4 | `Chassis:` | 底盘状态 |
| 5 | `Arm    :` | 机械臂状态 |
| 6 | `Pump   :` | 气泵状态 |
| 8 | `UART2 RX:` | NANO 接收字节数 |
| 9 | `Frames :` | 协议收发帧数 |
| 10 | `Buffer :` | 软件接收缓冲状态 |
| 12 | `Link   :` | 链路总体是否正常 |
| 13 | `Errors :` | 错误统计摘要 |
| 15 | `Frame  :` | 最近是否有新帧 |

注意：当前菜单代码调用 `CN_UART_Get_Diag(CN_UART_2, &uart2_diag)`，因此屏幕标签和 UART 诊断固定显示 UART2。如果把 NANO 协议切换到 UART7，协议统计仍来自 `Nano_COM_Get_Diag()`，但 UART 硬件错误这一行仍看 UART2。若后续长期使用 UART7 作为 NANO 口，建议同步把菜单诊断串口改为 `NANO_PROTOCOL_UART_PORT`。

## 5. 状态名称映射

菜单为了可读性，把协议层数值状态映射成英文单词显示。

### 5.1 系统状态

函数：

```c
Menu_System_State_Name()
```

| 数值 | 显示 | 含义 |
| --- | --- | --- |
| 0 | `Init` | 系统初始化中 |
| 1 | `Reset` | 外设复位中 |
| 2 | `Idle` | 空闲 |
| 3 | `Active` | 至少一个模块正在执行 |
| 4 | `EStop` | 急停锁止 |
| 5 | `Fault` | 故障预留 |

### 5.2 底盘状态

函数：

```c
Menu_Chassis_State_Name()
```

| 数值 | 显示 | 含义 |
| --- | --- | --- |
| 0 | `Idle` | 协议层认为底盘空闲 |
| 1 | `Run` | 正在运行速度控制 |
| 2 | `Rotate` | 正在执行定角旋转 |
| 3 | `Translate` | 正在执行定点平移 |
| 4 | `Stop` | 普通停止 |
| 5 | `Brake` | 刹停/抱死流程 |
| 6 | `Fault` | 故障预留 |

### 5.3 机械臂状态

函数：

```c
Menu_Arm_State_Name()
```

| 数值 | 显示 | 含义 |
| --- | --- | --- |
| 0 | `Idle` | 空闲 |
| 1 | `Moving` | 正在移动到目标点 |
| 2 | `Folding` | 正在回默认休息姿态 |
| 3 | `Hold` | 停止并锁持 |
| 4 | `Rejected` | 上一次命令被拒绝 |
| 5 | `Fault` | 故障预留 |

### 5.4 气泵状态

函数：

```c
Menu_Pump_State_Name()
```

| 数值 | 显示 | 含义 |
| --- | --- | --- |
| 0 | `Idle` | 空闲 |
| 1 | `Sucking` | 正在吸附检测 |
| 2 | `Sucked` | 已判定吸附 |
| 3 | `Release` | 放下流程中 |
| 4 | `Released` | 放下完成 |
| 5 | `Fault` | 故障预留 |

## 6. 每一行动态值含义

### 6.1 `Alive`

显示格式：

```text
Alive : <task_loop_count> Mark:<0/1>
```

来源：

- `nano_diag.task_loop_count`
- `g_menu_alive_mark`

`task_loop_count` 每执行一次 `Nano_COM_Task_Loop()` 加 1。如果这个数字持续变化，说明主循环还活着。

`Mark` 是菜单检测到 `task_loop_count` 变化后翻转的 0/1 心跳标记。它比纯数字更容易肉眼观察：如果 `Mark` 不再交替变化，说明主循环或屏幕刷新可能停住。

### 6.2 `System`

显示系统状态，例如：

```text
System : Idle
```

来源：

```c
nano_diag.system_state
```

如果显示 `EStop`，说明系统处于急停锁止状态，上位机必须发送 `RESET`，普通命令不会执行。

### 6.3 `Chassis`

显示底盘协议状态，例如：

```text
Chassis: Run
```

来源：

```c
nano_diag.chassis_state
```

它表示协议层状态，不完全等同于底层 `Movement_type_ENUM`。例如定角旋转完成后，底层会回到 `Movement_Running`，协议层检测到后会把 `chassis_state` 改回 `Idle` 并回事件。

### 6.4 `Arm`

显示机械臂协议状态，例如：

```text
Arm    : Moving
```

来源：

```c
nano_diag.arm_state
```

如果长时间保持 `Moving` 或 `Folding`，说明机械臂规划器可能还没结束，或者阶段等待时间设置过长。若显示 `Rejected`，说明目标可能不可达、进禁区或触发限位。

### 6.5 `Pump`

显示气泵协议状态，例如：

```text
Pump   : Sucked
```

来源：

```c
nano_diag.pump_state
```

`Sucked` 表示下位机已判定吸附成功，但当前流程中气泵不会立刻关闭，会继续运行直到上位机发送 release 或 30s 自动停泵。

### 6.6 `UART2 RX`

显示格式：

```text
UART2 RX: <rx_byte_count>
```

来源：

```c
nano_diag.rx_byte_count
```

这是 NANO 协议收到的总字节数。如果上位机持续发送数据，但该值不增加，优先检查：

- 串口是否接错。
- `NANO_PROTOCOL_UART_SELECT` 是否和实际接线一致。
- 串口波特率是否一致。
- UART 接收中断是否正常开启。

### 6.7 `Frames`

显示格式：

```text
Frames : R:<rx_frame_count> T:<tx_frame_count>
```

含义：

- `R`：成功解析出的完整协议帧数量。
- `T`：下位机发送的协议回包数量。

如果 `UART2 RX` 增加但 `R` 不增加，说明字节收到了但没有组成合法帧。重点看 `Errors` 行和协议格式。

### 6.8 `Buffer`

显示格式：

```text
Buffer : Ring:<rx_ring_occupied> Ready:<package_ready>
```

含义：

- `Ring`：NANO 软件接收环形缓冲区当前占用字节数。
- `Ready`：当前是否已有完整包等待业务处理。

正常情况下 `Ring` 不应长期很大。如果长期接近 `NANO_RX_RING_SIZE`，说明上位机发包太快或主循环处理不过来。

### 6.9 `Link`

显示：

```text
Link   : OK
```

或：

```text
Link   : Proto:<count>
```

当协议错误和 UART 硬件错误都为 0 时显示绿色 `OK`。只要任意错误累计非零，就显示协议错误总数。

### 6.10 `Errors`

显示：

```text
Errors : None
```

或：

```text
Errors : Uart:<count>
```

`Uart` 错误总数包括：

- UART 硬件错误。
- 接收溢出。
- 帧错误。
- 噪声错误。
- TX FIFO 写入失败。

如果这里持续增加，说明不只是协议格式问题，可能有串口硬件层面的异常。

### 6.11 `Frame`

显示：

```text
Frame  : Updated
```

或：

```text
Frame  : No new frame
```

如果 `rx_frame_count` 或 `tx_frame_count` 相比上次刷新发生变化，显示 `Updated`。否则显示 `No new frame`。

这是用于肉眼判断“最近是否真的有收发包”的简化提示。

## 7. 诊断字段来源

菜单使用两个诊断结构：

```c
Nano_COM_Diag_t nano_diag;
CN_UART_Diag_t uart2_diag;
```

`Nano_COM_Diag_t` 来自：

```c
Nano_COM_Get_Diag(&nano_diag);
```

`CN_UART_Diag_t` 来自：

```c
CN_UART_Get_Diag(CN_UART_2, &uart2_diag);
```

NANO 协议诊断更偏向协议解析和主循环状态；UART 诊断更偏向硬件串口和发送 FIFO 状态。

## 8. 常见现象判断

### 8.1 屏幕亮但数值不变

如果标题能显示，但 `Alive` 数字和 `Mark` 不变：

- 主循环可能卡死。
- `Menu_poll()` 可能没有被调用。
- `PrintFlag` 可能没有被 PIT2 置位。
- 系统可能停在某个阻塞函数中。

### 8.2 `UART2 RX` 不增加

说明下位机协议层没有收到字节。检查：

- 上位机端口是否选错。
- 波特率是否 115200。
- TX/RX 是否交叉连接。
- NANO 协议当前选择的是 UART2 还是 UART7。
- UART 初始化是否执行。

### 8.3 `UART2 RX` 增加但 `Frames R` 不增加

说明接收到了字节，但协议解析失败。检查：

- 帧头是否 `AA 55`。
- 版本是否 `01`。
- `LEN` 是否正确。
- checksum 是否从 `VER` 加到 payload。
- 帧尾是否 `0D 0A`。

如果 `Link` 显示 `Proto`，说明协议错误计数已经增加。

### 8.4 `Ring` 越来越大

说明上位机发送速度超过下位机主循环解析速度。建议：

- 降低上位机发包频率。
- 速度控制保持 20~50Hz。
- 不要无等待连续刷大量状态查询。

### 8.5 `Errors Uart` 增加

说明串口硬件层面有异常，常见原因：

- 波特率不一致。
- 接线过长或干扰大。
- 上位机短时间大量发送导致 overrun。
- MCU 主循环或中断被其他高耗时任务影响。

## 9. 后续维护建议

1. 如果 NANO 协议口长期改为 UART7，应把菜单中的 `UART2 RX` 标签和 `CN_UART_Get_Diag(CN_UART_2, ...)` 改为协议选择宏对应串口。
2. 如果屏幕刷新仍闪烁，不要整屏清屏，继续保持“固定标签一次绘制、动态值局部更新”的结构。
3. 如果要显示更多状态，不建议超过 16 行；可以减少低频诊断项，优先保留 Alive、System、Chassis、Arm、Pump、Frames 和 Link。
