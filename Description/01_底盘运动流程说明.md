# 底盘运动流程说明

## 1. 模块定位

底盘运动代码主要位于：

- `Code/ChaseNum1_Movement.c`
- `Code/ChaseNum1_Movement.h`
- `Code/ChaseNum1_Motor.c`
- `Code/ChaseNum1_Motor.h`
- `Code/ChaseNum1_ENC.c`
- `Code/ChaseNum1_IMU.c`
- `Code/ChaseNum1_NanoProtocol.c`
- `USER/main.c`

底盘控制分为两层：

1. 运动功能层：`ChaseNum1_Movement.c` 根据当前运动模式生成四个轮子的速度目标，并调用电机速度闭环。
2. 协议调度层：`ChaseNum1_NanoProtocol.c` 接收上位机命令，把上位机变量映射为下位机内部变量，再调用 `CN_set_movement()`。

真正周期执行底盘闭环的是 `USER/main.c` 中的 `CN_PIT1_CALLBACK()`：

```c
void CN_PIT1_CALLBACK(void){
   CN_Movement_ctrl_CALLBACK(1);
}
```

也就是说，底盘运动不是在收到串口命令的瞬间一次性完成，而是在 1ms 定时中断节拍里持续执行。上位机只是改变目标值或运动模式。

## 2. 坐标和方向约定

底盘坐标在 `Car_Movement_struct` 的注释中定义，按照俯视视角：

- 车头方向为 `Y` 正方向。
- 车身右侧为 `X` 正方向。
- 车体竖直向上为 `Z` 正方向。
- 绕 `Z` 轴旋转遵循右手定则，俯视逆时针为正，顺时针为负。

底盘四轮速度结构使用：

- `M_FL`：左前轮。
- `M_FR`：右前轮。
- `M_BL`：左后轮。
- `M_BR`：右后轮。

当前轮速合成公式位于 `CN_CAR_vel_CL_CALLBACK()`：

```c
Vel_aim.M_FL_Vel = y + x + anv;
Vel_aim.M_FR_Vel = y - x - anv;
Vel_aim.M_BL_Vel = y - x + anv;
Vel_aim.M_BR_Vel = y + x - anv;
```

其中 `x` 是车身横向速度，`y` 是车身纵向速度，`anv` 是旋转分量。这个公式决定了按键或上位机速度方向最终如何分配到四个轮子。

## 3. 初始化流程

底盘相关初始化在 `USER/main.c` 中按如下顺序执行：

1. `CN_Motor_init()`：初始化电机 PWM 引脚、定时器等底层资源。
2. `CN_TIM_Motor_PWMOUT_ENA()`：使能电机 PWM 输出。
3. `CN_stop_Motor_Duty()`：初始化后立刻清零输出，避免刚上电乱转。
4. `CN_TIM2345_ENC_init()`：初始化四路编码器。
5. `CN_move_init()`：初始化底盘运动模块。
6. `CN_3rd_Party_JY61_IMU_init()`：初始化 IMU，供航向角闭环使用。
7. `CN_PIT_1_init_ms(1,1)`：开启 1ms 底盘控制节拍。
8. `CN_PIT_2_init_ms(1,2)`：开启 1ms 编码器读取和协议 tick 节拍。

`CN_move_init()` 内部初始化：

- 车身速度环：`CN_CAR_vel_CL_init()`。
- 车身角度环：`CN_CAR_yaw_CL_init()`。
- 旋转分量：`CN_CAR_anv_CL_init()`。
- 定点平移位置记录：`CN_CAR_pos_CL_init()`。
- 初始运动模式：`Movement_Breaking`。

## 4. 运动模式总览

底盘运动模式由 `Movement_type_ENUM` 表示：

| 模式 | 枚举值 | 含义 |
| --- | --- | --- |
| `Movement_Breaking` | 0 | 刹停/放松控制流程 |
| `Movement_Running` | 1 | 正常运行，支持全向平移和航向保持 |
| `Movement_Rotation` | 2 | 相对当前角度旋转指定角度 |
| `Movement_Translation` | 3 | 相对当前位置定向定速平移指定距离 |

外部统一通过：

```c
void CN_set_movement(Car_Movement_struct movement, Movement_type_ENUM movement_type);
```

切换运动模式。该函数不是简单赋值，它会根据目标模式做衔接处理，比如清 PID、保持当前 yaw、取消刹车闭环、初始化平移累计量等。

当前模式可通过：

```c
Movement_type_ENUM CN_Chassis_Get_Movement_Type(void);
```

读取。统一协议状态机正是通过这个接口判断旋转和平移是否已经结束。

## 5. `Movement_Running` 正常运行模式

### 5.1 功能

`Movement_Running` 是底盘最常用模式，用于：

- 上位机连续发送速度控制。
- 循迹或全向平移。
- 零速度姿态保持。

即使速度为 0，也不是断电放手，而是保持当前航向角闭环。

### 5.2 进入模式

进入函数：

```c
static void CN_Chassis_Enter_Run(Car_Movement_struct movement, uint8_t keep_yaw_aim);
```

当从其他模式切入 run 时：

- `YAW_aim = YAW_now`，把当前车身角度作为新的保持目标。
- 重置车身 yaw PID。
- 重置速度斜坡参考值。
- 重置四轮速度 PID。

当连续保持在 run 模式时：

- `keep_yaw_aim = 1`。
- 不重置 `YAW_aim`，这样上位机连续发送速度指令时不会让航向目标跳变。

### 5.3 运行过程

在 `CN_Movement_ctrl_CALLBACK()` 中，run 模式每 1ms 执行速度闭环，每 10ms 执行一次 yaw 角度闭环：

```c
YAW_aim = CN_yaw_add(YAW_aim, YAW_acc * 0.01f);
CN_CAR_yaw_CL_CALLBACK(10000U);
CN_CAR_vel_CL_CALLBACK(1000U);
```

`YAW_acc` 由 `CN_CAR_rotation_set_aim()` 设置，来自上位机 running 模式中的角速度输入。当前实现不是把上位机角速度直接丢进轮速解算，而是把它作为航向目标变化率累加到 `YAW_aim`，然后由航向角 PID 输出 `target_anv`。

这意味着：

- 上位机 `wz > 0` 时，目标航向按正方向连续变化。
- 下位机用角度环追踪变化后的 `YAW_aim`。
- 如果 `wz = 0`，`YAW_aim` 不再变化，车身会保持当前目标角度。

### 5.4 速度斜坡

速度斜坡由以下宏控制：

```c
#define CHASSIS_VEL_RAMP_ENABLE  1U
#define CHASSIS_VEL_RAMP_ACC     15.0f
```

`target_VelX` 和 `target_VelY` 不会立刻进入轮速解算，而是通过 `CN_Chassis_Approach_Float()` 逐步逼近，减少速度突变。由于底盘轮子死区较大，低速段仍可能不明显，但中高速目标变化会更平顺。

## 6. `Movement_Rotation` 定角旋转模式

### 6.1 功能

`Movement_Rotation` 用于让底盘相对当前姿态旋转指定角度。旋转完成后自动切回 `Movement_Running` 的零速度姿态保持状态。

上位机发送：

- 目标角度：任意正负角度，单位 deg。
- 最大角速度：上位机输入 1~100，协议层映射到下位机内部 1~10。

### 6.2 进入模式

进入函数：

```c
static void CN_Chassis_Enter_Rotation(Car_Movement_struct movement);
```

进入时记录：

- `YAW_inital = YAW_now`：进入旋转前的航向。
- `YAW_pre = YAW_now`：上一周期 yaw，用于累计真实旋转量。
- `YAW_gain = 0`：已经累计旋转的角度。
- `target_yaw = movement.Car_angle`：目标相对旋转角。
- `g_chassis_rotation_target_abs_yaw = CN_yaw_add(YAW_inital, target_yaw)`：旋转完成后希望保持的绝对航向。

同时清零平移速度、旋转分量和 PID，避免从 run 或 translation 切换过来时残留目标影响旋转。

### 6.3 运行过程

旋转模式不再使用角速度闭环，而是直接设置 `target_anv` 参与底盘解算。

每个周期先用 IMU yaw 差分累计实际旋转量：

```c
yaw_delta = YAW_now - YAW_pre;
```

如果跨过 `±180°`，代码会修正跳变：

```c
if (yaw_delta > 180.0f) yaw_delta -= 360.0f;
else if (yaw_delta < -180.0f) yaw_delta += 360.0f;
```

然后：

```c
YAW_gain += yaw_delta;
remaining = target_yaw - YAW_gain;
```

当剩余角度大于减速距离时，使用最大角速度；当进入减速距离时线性减速：

```c
#define CHASSIS_ROTATION_SLOW_ANGLE_DEG  20.0f
#define CHASSIS_ROTATION_MIN_ANGVEL      1.0f
```

如果剩余角度已经小于：

```c
#define CHASSIS_ROTATION_ANGLE_TOL_DEG   1.0f
```

则调用：

```c
CN_Chassis_Finish_To_Run(g_chassis_rotation_target_abs_yaw);
```

把底盘切回 run 零速度，并保持旋转目标绝对航向。

### 6.4 到位回包

底层运动模块本身不直接发串口回包。统一协议状态机在 `Nano_COM_Update_Chassis()` 中检测：

```c
if (g_chassis_state == NANO_CHASSIS_ROTATE &&
    CN_Chassis_Get_Movement_Type() == Movement_Running)
```

一旦旋转模式自动回到 `Movement_Running`，协议层发送事件：

```text
EVENT_CHASSIS_ROTATE_DONE = 0x10
```

## 7. `Movement_Translation` 定点平移模式

### 7.1 功能

`Movement_Translation` 用于相对当前位置平移一个指定距离，同时保持进入该模式时的车身姿态。

当前实现按用户要求保持简单：

- 不做额外横向纠偏。
- 相信四个轮子的编码器合成位移。
- 根据目标方向的投影距离判断进度。
- 接近目标后减速，避免在目标点来回振荡。

### 7.2 上位机和下位机量纲

上位机发送：

- `dx_cm`：相对 X 位移，单位 cm，范围 -1000~1000。
- `dy_cm`：相对 Y 位移，单位 cm，范围 -1000~1000。
- `speed`：速度百分量，范围 1~100。

协议层映射：

- `dx_cm/dy_cm` 线性映射到下位机内部 -50000~50000。
- `speed` 映射到下位机内部 1~20。

这意味着当前下位机内部平移距离单位不是严格物理 cm，而是和编码器合成量一致的内部计数尺度。若后续完成底盘里程标定，应统一修改映射系数。

### 7.3 进入模式

进入函数：

```c
static void CN_Chassis_Enter_Translation(Car_Movement_struct movement);
```

最终调用：

```c
CN_CAR_pos_CL_set_aim(movement);
```

该函数做以下事情：

1. 记录进入平移时的车身姿态：

```c
initial_yaw = YAW_now;
YAW_aim = initial_yaw;
```

2. 清零相对位移：

```c
cur_x = 0.0f;
cur_y = 0.0f;
```

3. 计算目标总距离：

```c
target_distance = sqrtf(target_pose.x * target_pose.x + target_pose.y * target_pose.y);
```

4. 计算目标方向单位向量：

```c
dir_x = target_pose.x / target_distance;
dir_y = target_pose.y / target_distance;
```

5. 设置最大平移速度，并限制到：

```c
#define CHASSIS_TRANSLATION_MAX_SPEED 20.0f
```

6. 清零速度参考、旋转目标和 PID。

### 7.4 位移合成

位置回调函数：

```c
void CN_CAR_pos_CL_CALLBACK(uint32_t us_time);
```

读取编码器增量：

```c
fl_delta = ENC_data[3];
fr_delta = ENC_data[1];
bl_delta = ENC_data[2];
br_delta = ENC_data[0];
```

根据麦轮运动关系合成底盘相对位移：

```c
delta_x = ((FL - FR - BL + BR) / 4.0f) / M_TO_ENC_FACTOR;
delta_y = ((FL + FR + BL + BR) / 4.0f) / M_TO_ENC_FACTOR;
```

再累计：

```c
cur_x += delta_x;
cur_y += delta_y;
```

这里的 `M_TO_ENC_FACTOR` 当前为 `1.0f`，说明没有做物理单位换算。平移是否准确，直接依赖编码器方向、轮径、麦轮安装方向和该系数标定。

### 7.5 进度和减速

平移不是分别判断 `cur_x` 和 `cur_y`，而是把当前位移投影到目标方向：

```c
progress = cur_x * dir_x + cur_y * dir_y;
distance_to_go = total_distance - progress;
```

这样目标是斜向时，也能用同一个剩余距离做减速。

减速距离：

```c
#define CHASSIS_TRANSLATION_SLOW_DISTANCE 2500.0f
```

单位是下位机内部位移单位，和 `target_pose`、`cur_x/cur_y`、`distance_to_go` 一致，不是 cm。当前上位机 1000cm 会映射到内部 50000，因此 `2500` 约等于上位机 50cm 对应的内部距离。

如果剩余距离小于该值：

```c
speed_target = max_speed * distance_to_go / CHASSIS_TRANSLATION_SLOW_DISTANCE;
```

速度参考再通过：

```c
#define CHASSIS_TRANSLATION_ACC 150.0f
```

逐步逼近目标速度，避免速度突变。

### 7.6 到位判断

到位容差：

```c
#define CHASSIS_TRANSLATION_POS_TOL 100.0f
```

单位同样是内部位移单位，不是 cm。

进入容差后：

1. 平移目标速度设为 0。
2. 速度参考逐步降到 0。
3. 如果四个轮子的最大速度小于：

```c
#define CHASSIS_TRANSLATION_REACH_VEL_EPS 1.0f
```

并持续：

```c
#define CHASSIS_TRANSLATION_REACH_CONFIRM_MS 50U
```

则认为平移完成。

完成后 `CN_Movement_ctrl_CALLBACK()` 调用：

```c
CN_Chassis_Finish_To_Run(initial_yaw);
```

底盘回到 run 零速度并保持进入平移前的姿态。

### 7.7 到位回包

协议层在 `Nano_COM_Update_Chassis()` 检测：

```c
if (g_chassis_state == NANO_CHASSIS_TRANSLATE &&
    CN_Chassis_Get_Movement_Type() == Movement_Running)
```

发送事件：

```text
EVENT_CHASSIS_TRANS_DONE = 0x11
```

## 8. `Movement_Breaking` 刹停模式

### 8.1 功能

`Movement_Breaking` 用于收到上位机 BRAKE 或系统急停时先抱死轮胎，再在车辆静止后放开控制。它和普通 STOP 不一样：

- STOP：进入 run 零速度，保持姿态闭环。
- BRAKE：短时间闭环抱死，确认静止后清 PWM 放松控制。

### 8.2 进入刹停

进入函数：

```c
static void CN_Chassis_Brake_Start(void);
```

主要动作：

- `YAW_aim = YAW_now`，用当前车身姿态作为抱死阶段目标。
- 设置车身速度目标为 0。
- 设置旋转目标为 0。
- 重置轮速 PID。
- 标记 `g_chassis_brake_closed_loop_active = 1`。

### 8.3 刹停过程

在 `Movement_Breaking` 状态下，如果闭环抱死仍有效：

- 每 10ms 执行 yaw 角度闭环。
- 每 1ms 执行四轮速度闭环，速度目标为 0。
- 调用 `CN_Chassis_Brake_Update(ms)` 判断是否可以放手。

判断条件：

```c
#define CHASSIS_BRAKE_STILL_VEL_EPS    1.0f
#define CHASSIS_BRAKE_STILL_CONFIRM_MS 100U
#define CHASSIS_BRAKE_MAX_HOLD_MS      1000U
```

如果四轮速度足够小并持续 100ms，或者抱死超过 1000ms，就调用 `CN_Intr_Movement()` 清 PWM 放松控制。

放松控制后，代码仍会执行：

```c
YAW_aim = YAW_now;
```

这样如果车辆被人工转动，再次进入 run 时不会猛地回到刹车前角度。

## 9. 电机速度闭环

四轮速度闭环在 `Code/ChaseNum1_Motor.c` 的：

```c
void CN_Motor_vel_CL_CALLBACK(uint32_t us_time);
```

中执行。

当前编码器读取对应关系：

```c
FL <- ENC_data[3]
FR <- ENC_data[1]
BL <- ENC_data[2]
BR <- ENC_data[0]
```

PID 输出写入 `Duty_now`，再由 `CN_set_Motor_Duty()` 根据正负方向输出到每个电机的两路 PWM。

底盘方向问题通常需要重点检查三处：

1. 编码器增量正负是否符合“车轮前进为正”。
2. `CN_set_Motor_Duty()` 中每个电机两路 PWM 是否和当前接线一致。
3. `CN_CAR_vel_CL_CALLBACK()` 的四轮合成公式是否和麦轮安装方向一致。

## 10. 上位机变量范围和映射

统一协议中的底盘映射在 `Code/ChaseNum1_NanoProtocol.c` 中定义。

### 10.1 RUN 速度

上位机发送：

- `vx`：-100~100。
- `vy`：-100~100。
- `wz`：-100~100。

映射关系：

| 上位机变量 | 上位机范围 | 下位机内部范围 | 说明 |
| --- | --- | --- | --- |
| `vx` | -100~100 | -20~-1、0、1~20 | 非零输入带最小输出，克服低速死区 |
| `vy` | -100~100 | -20~-1、0、1~20 | 同上 |
| `wz` | -100~100 | -200~200 | 作为 `YAW_acc` 累加航向目标 |

注意：`vx/vy` 输入 0 会输出 0；输入绝对值很小但非零时会映射到至少 1 的内部速度。

### 10.2 ROTATE 旋转

上位机发送：

- `angle_deg`：任意角度，正负决定旋转方向。
- `max_wz`：1~100。

映射关系：

```text
max_wz 1~100 -> 下位机内部 1~10
```

旋转过程直接把内部角速度写入 `target_anv`，不经过 yaw 角速度闭环。

### 10.3 TRANSLATE 平移

上位机发送：

- `dx_cm`：-1000~1000。
- `dy_cm`：-1000~1000。
- `speed`：1~100。

映射关系：

| 上位机变量 | 上位机范围 | 下位机内部范围 |
| --- | --- | --- |
| `dx_cm` | -1000~1000 | -50000~50000 |
| `dy_cm` | -1000~1000 | -50000~50000 |
| `speed` | 1~100 | 1~20 |

## 11. 协议层对底盘的调度

底盘命令由 `Nano_COM_Process_Package()` 处理。

支持命令：

| 命令 | CMD | 载荷 | 执行动作 |
| --- | --- | --- | --- |
| `CHASSIS_RUN` | `0x10` | `<fff>` | 映射 vx/vy/wz 后进入 `Movement_Running` |
| `CHASSIS_STOP` | `0x11` | 无 | 进入 run 零速度姿态保持 |
| `CHASSIS_BRAKE` | `0x12` | 无 | 进入 `Movement_Breaking` |
| `CHASSIS_ROTATE_TO` | `0x13` | `<ff>` | 进入 `Movement_Rotation` |
| `CHASSIS_TRANSLATE_REL` | `0x14` | `<fff>` | 进入 `Movement_Translation` |
| `CHASSIS_GET_STATE` | `0x15` | 无 | 回传底盘状态 |

运行速度命令必须周期发送。超时检测：

```c
#define NANO_CHASSIS_RUN_TIMEOUT_MS 500U
```

如果超过 500ms 没有新的 run 命令，协议层自动发送零速度 run，并产生：

```text
EVENT_CHASSIS_TIMEOUT_STOP = 0x12
```

这个超时停止不是刹停，不会进入短时抱死后放手流程。

## 12. 常见问题排查

### 12.1 旋转一卡一卡

优先检查：

- 上位机是否周期性发送了 run 命令打断 rotation。
- IMU `YAW_now` 是否跳变或噪声过大。
- `CHASSIS_ROTATION_SLOW_ANGLE_DEG` 是否过大导致过早减速。
- `CHASSIS_ROTATION_MIN_ANGVEL` 是否低于底盘死区。
- 电机速度 PID 是否有饱和、积分残留或编码器方向错误。

### 12.2 平移距离不准

优先检查：

- `M_TO_ENC_FACTOR` 是否仍为 1。
- 四轮编码器方向是否正确。
- 麦轮安装方向是否和解算公式一致。
- 上位机 cm 到内部距离的映射是否已按实车标定。

### 12.3 BRAKE 后再 RUN 会不会猛转

当前代码在放松控制后持续 `YAW_aim = YAW_now`，因此人工转动车身后再进入 run，一般不会猛地回到刹车前姿态。若仍出现猛转，重点检查是否有其他代码在进入 run 前重新写入旧的 `YAW_aim`。

## 13. 后续维护建议

1. 如果重新标定底盘位移，应统一修改 `M_TO_ENC_FACTOR` 和协议中的平移距离映射。
2. 如果修改电机接线，必须同步检查 `CN_set_Motor_Duty()` 和编码器对应关系。
3. 如果发现低速斜坡无效，优先提高最小非零速度或死区补偿，而不是盲目增大 PID。
4. 如果上位机高频控制，建议 run 命令频率保持在 20~50Hz，避免串口压力过大。
