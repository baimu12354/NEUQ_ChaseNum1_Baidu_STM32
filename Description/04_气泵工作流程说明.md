# 气泵工作流程说明

## 1. 模块定位

气泵相关代码主要位于：

- `Code/ChaseNum1_Pump.c`
- `Code/ChaseNum1_Pump.h`
- `Code/ChaseNum1_Typedef.h`
- `Code/ChaseNum1_NanoProtocol.c`

当前气泵模块负责：

1. PE5 输出 PWM 控制气泵转速。
2. PE6 使用 TIM15_CH2 输入捕获测量反馈信号频率。
3. 对频率做滤波，降低单次测量抖动影响。
4. 根据频率阈值和滑动计数判断是否吸附成功。
5. 吸附成功后保持气泵运行，并通知协议层发送吸附完成事件。
6. 上位机发送 release 后关闭气泵，并等待固定时间后认为工件释放。
7. 如果气泵持续运行超过 30s，则自动停泵并让协议层上报超时停泵事件。

## 2. 硬件资源

### 2.1 PWM 输出

气泵 PWM 输出使用：

```text
PE5 -> TIM15_CH1
```

核心宏：

```c
#define PUMP_PWM_PERIOD_COUNT 10000U
#define PUMP_DEFAULT_DUTY     10000U
```

当前默认占空比为 10000/10000，也就是满占空比。如果需要降低气泵转速，可以修改 `PUMP_DEFAULT_DUTY`。

占空比写入函数：

```c
static void CN_Pump_Apply_Duty(uint16_t duty);
```

该函数会先调用 `CN_Pump_Clamp_Duty()` 把 duty 限制在 `0~PUMP_PWM_PERIOD_COUNT`，再写入 TIM15 CH1 比较值。

### 2.2 反馈输入

气泵反馈使用：

```text
PE6 -> TIM15_CH2
```

反馈信号是频率/占空比型信号。当前代码只使用上升沿周期计算频率，没有使用 ADC。

定时器相关宏：

```c
#define PUMP_TIM_BASE_CLOCK_HZ       200000000U
#define PUMP_TIM_PRESCALER_COUNT     10U
#define PUMP_TIM_TICK_HZ             (PUMP_TIM_BASE_CLOCK_HZ / PUMP_TIM_PRESCALER_COUNT)
#define PUMP_FEEDBACK_IC_FILTER      0U
```

因此当前测频 tick 频率为：

```text
20 MHz
```

也就是 1 tick = 0.05us。

## 3. 全局状态结构

气泵状态保存在 `Pump_Handle_Struct`：

```c
typedef struct{
    uint8_t Pump_on;
    uint8_t IfSucked;
    uint32_t SuckStrength;
    float FeedbackFreqHz;
    uint32_t FeedbackPeriodTicks;
} Pump_Handle_Struct;
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `Pump_on` | 气泵是否正在运行 |
| `IfSucked` | 是否已判定吸附成功 |
| `SuckStrength` | 当前简单记录的吸附强度，实际存的是频率整数值 |
| `FeedbackFreqHz` | PE6 测得并滤波后的反馈频率，单位 Hz |
| `FeedbackPeriodTicks` | 最近反馈周期，单位 TIM15 tick |

## 4. 初始化流程

初始化入口：

```c
void CN_Pump_init(void);
```

执行过程：

1. 调用 `CN_Pump_TIM_init()` 初始化 TIM15 的 PWM 输出和输入捕获。
2. 设置 `Pump_Handle.Pump_on = 0`，默认不开泵。
3. 调用 `CN_Pump_Feedback_Reset()` 清空频率测量状态。
4. 调用 `CN_Pump_Suck_Detect_Reset()` 清空吸附判断缓存。

`CN_Pump_TIM_init()` 负责配置：

- TIM15 基本计数器。
- PE5 复用为 TIM15_CH1 PWM 输出。
- PE6 复用为 TIM15_CH2 输入捕获。
- CH2 上升沿捕获。
- TIM15 溢出中断，用于扩展输入捕获周期。

## 5. 开泵流程

开泵接口：

```c
void CN_Pump_Start(void);
```

执行过程：

1. 设置 PWM duty：

```c
CN_Pump_Apply_Duty(PUMP_DEFAULT_DUTY);
```

2. 标记气泵运行：

```c
Pump_Handle.Pump_on = 1U;
```

3. 清空吸附检测缓存：

```c
CN_Pump_Suck_Detect_Reset();
```

4. 开启反馈测频：

```c
CN_Pump_Feedback_Start();
```

5. 记录启动时间：

```c
g_pump_start_ms = HAL_GetTick();
```

当前设计是“只有气泵开启时才测频”。如果 `Pump_on=0`，输入捕获回调即使进来，也会忽略并复位测频状态。

## 6. 停泵流程

停泵接口：

```c
void CN_Pump_Stop(void);
```

执行过程：

1. PWM duty 写 0。
2. `Pump_Handle.Pump_on = 0`。
3. 停止 PE6 反馈捕获。
4. 清空测频状态。

停泵不会自动改变协议层状态，协议层在 `Nano_COM_Update_Pump()` 中根据 `Pump_on` 和当前协议状态决定是否发送超时停泵事件。

## 7. 频率测量流程

### 7.1 输入捕获回调

输入捕获回调：

```c
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim);
```

该函数由 STM32 HAL 在 TIM15_CH2 捕获到上升沿时自动调用，不需要用户手动调用。

处理逻辑：

1. 判断是否为 TIM15 CH2。
2. 如果气泵未开启，复位反馈状态并返回。
3. 读取当前捕获值。
4. 结合定时器溢出计数，组成扩展时间戳。
5. 用当前时间戳减去上一次时间戳，得到周期 tick：

```c
period_ticks = current_total_ticks - last_total_ticks;
```

6. 把周期 tick 写入滤波缓冲：

```c
CN_Pump_Freq_Filter_Push(period_ticks);
```

### 7.2 溢出扩展

TIM15 计数器会溢出。为了测量较低频率信号，代码通过：

```c
void CN_Pump_TIM15_PeriodElapsedCallback(void);
```

记录溢出次数，输入捕获时把溢出次数和捕获值拼成更长的时间戳。

如果长时间没有新捕获，超过：

```c
#define PUMP_FEEDBACK_TIMEOUT_MS 200U
```

则认为反馈超时，清空测频状态，避免旧频率长期保留。

## 8. 频率滤波

气泵反馈频率波动较大，当前不是直接用相邻两个上升沿算出的瞬时频率做判断，而是先对周期做缓冲和滤波。

周期滤波缓冲：

```c
#define PUMP_FREQ_PERIOD_FILTER_SIZE 10U
```

流程在：

```c
static float CN_Pump_Freq_Filter_Update(void);
```

中完成。

### 8.1 去极值平均

主循环读取缓冲区时会临时关闭中断，复制输入捕获写入的周期样本。若样本数不少于 4，则去掉最大周期和最小周期，再求平均。

这样可以抑制偶发异常脉冲：

- 最大周期可能来自丢边沿或中间停顿。
- 最小周期可能来自毛刺或噪声。

### 8.2 周期转频率

平均周期 tick 转频率：

```c
freq = PUMP_TIM_TICK_HZ / avg_period_ticks;
```

其中 `PUMP_TIM_TICK_HZ` 当前是 20MHz。

### 8.3 IIR 低通滤波

最终频率再做一阶 IIR：

```c
#define PUMP_FREQ_IIR_ALPHA 0.2f
```

形式为：

```text
filtered = old * (1 - alpha) + new * alpha
```

`alpha=0.2` 表示新值占 20%，旧值占 80%，能明显降低显示和判断抖动。若响应太慢可适当增大，若仍抖动可适当减小。

## 9. 吸附判定逻辑

当前吸附判定基于频率阈值，宏定义：

```c
#define PUMP_SUCK_DETECT_ENABLE         1U
#define PUMP_SUCK_FREQ_THRESHOLD_HZ     53.00f
#define PUMP_SUCK_CHECK_INTERVAL_MS     20U
#define PUMP_SUCK_FREQ_FILTER_SIZE      100U
#define PUMP_SUCK_FREQ_CONFIRM_COUNT    20U
#define PUMP_SUCK_FORCE_DONE_TIMEOUT_MS 5000U
```

### 9.1 当前判定方向

当前代码判断：

```c
freq_hz >= PUMP_SUCK_FREQ_THRESHOLD_HZ
```

则该采样记为“满足吸附条件”。

也就是说，当前工程认为：

```text
反馈频率大于等于阈值 -> 倾向于判定吸附
```

这是按当前代码实现说明。若后续实测再次确认“压力越大频率越小”，则应把比较方向改成 `<=` 并同步更新本说明。

### 9.2 滑动计数

每隔 20ms 调用一次：

```c
CN_Pump_Suck_Detect_Update(freq_hz);
```

该函数把当前判断结果写入长度为 100 的环形缓冲：

```c
g_pump_suck_freq_buffer[100]
```

然后统计当前有效样本中满足条件的次数。如果次数达到：

```c
PUMP_SUCK_FREQ_CONFIRM_COUNT = 20
```

则：

```c
Pump_Handle.IfSucked = 1U;
```

这样做的目的不是要求连续 20 次满足，而是在最近一段时间内满足次数达到阈值即可，能抵抗反馈频率上下浮动。

### 9.3 强制吸附完成超时

如果气泵启动后超过：

```c
#define PUMP_SUCK_FORCE_DONE_TIMEOUT_MS 5000U
```

仍没有检测到吸附，代码会强制：

```c
Pump_Handle.IfSucked = 1U;
```

这个设计是为了避免上位机一直等不到吸附完成事件。它适合调试阶段或任务流程必须继续的场景，但如果真实任务需要严格判断吸附成功，应谨慎调整或关闭该宏。

### 9.4 自动停泵

自动停泵宏：

```c
#define PUMP_AUTO_STOP_TIMEOUT_MS 30000U
```

如果气泵运行超过 30s，`CN_Pump_Task_Loop()` 会调用：

```c
CN_Pump_Stop();
```

协议层检测到 `Pump_on=0` 且状态仍为 `SUCKING/SUCKED` 时，会发送：

```text
EVENT_PUMP_TIMEOUT_STOP = 0x32
```

## 10. 主循环任务

气泵周期任务入口：

```c
void CN_Pump_Task_Loop(void);
```

该函数在 `Nano_COM_Task_Loop()` 中被调用。

执行逻辑：

1. 如果 `Pump_on=0`，直接返回，不测频、不判断。
2. 调用 `CN_Pump_Get_Feedback_Freq_Hz()` 更新滤波频率。
3. 每 20ms 执行一次吸附判定。
4. 检查 5s 强制完成。
5. 检查 30s 自动停泵。

## 11. 协议层气泵流程

气泵协议命令由 `Nano_COM_Process_Package()` 处理。

### 11.1 吸附命令

上位机发送：

```text
MODULE = PUMP
CMD    = PUMP_SUCK = 0x30
LEN    = 0
```

下位机动作：

1. 如果气泵正在吸附、已吸附或释放中，返回 `NACK BUSY`。
2. 否则调用 `CN_Pump_Start()`。
3. 协议状态置为 `NANO_PUMP_SUCKING`。
4. 返回 ACK。

吸附检测成功后，协议层在 `Nano_COM_Update_Pump()` 中看到：

```c
Pump_Handle.IfSucked != 0
```

于是状态改为 `NANO_PUMP_SUCKED`，并发送：

```text
EVENT_PUMP_SUCK_DONE = 0x30
```

注意：吸附成功后不会自动停泵，气泵继续运行。

### 11.2 放下命令

上位机发送：

```text
MODULE = PUMP
CMD    = PUMP_RELEASE = 0x31
LEN    = 0
```

下位机动作：

1. 调用 `CN_Pump_Stop()` 关闭气泵。
2. 清除 `Pump_Handle.IfSucked`。
3. 协议状态置为 `NANO_PUMP_RELEASING`。
4. 记录释放开始时间。
5. 返回 ACK。

协议层等待：

```c
#define NANO_PUMP_RELEASE_WAIT_MS 500U
```

到时后发送：

```text
EVENT_PUMP_RELEASE_DONE = 0x31
```

这里的 500ms 是软件认为工件释放完成的等待时间，不是传感器检测结果。实际值应根据吸盘泄压和工件脱落测试调整。

### 11.3 状态查询

上位机发送：

```text
MODULE = PUMP
CMD    = PUMP_GET_STATE = 0x32
LEN    = 0
```

下位机返回 `PUMP_STATE`，包含：

- 气泵协议状态。
- `Pump_on`。
- `IfSucked`。
- 当前滤波频率。
- `SuckStrength`。

## 12. 调参建议

### 12.1 吸附阈值

宏：

```c
#define PUMP_SUCK_FREQ_THRESHOLD_HZ 53.00f
```

调试方法：

1. 不吸附时读取 `PUMP_STATE` 中的 `feedback_hz`。
2. 吸附稳定后读取 `feedback_hz`。
3. 取两种状态中间较保守的值作为阈值。
4. 如果波动重叠明显，提高缓冲判定的鲁棒性，而不是只调一个阈值。

### 12.2 判定次数

宏：

```c
#define PUMP_SUCK_FREQ_FILTER_SIZE   100U
#define PUMP_SUCK_FREQ_CONFIRM_COUNT 20U
```

在 20ms 检测周期下，100 个样本大约覆盖 2s。确认次数 20 表示最近窗口里约 20% 样本满足阈值即可判定。

如果误判吸附：

- 增大 `PUMP_SUCK_FREQ_CONFIRM_COUNT`。
- 或减小窗口但增大比例。

如果判定太慢：

- 减小 `PUMP_SUCK_FREQ_FILTER_SIZE`。
- 或减小 `PUMP_SUCK_FREQ_CONFIRM_COUNT`。

### 12.3 频率滤波

宏：

```c
#define PUMP_FREQ_PERIOD_FILTER_SIZE 10U
#define PUMP_FREQ_IIR_ALPHA          0.2f
```

如果频率显示仍跳动很大：

- 增大周期滤波窗口。
- 减小 IIR alpha。

如果吸附状态变化响应太慢：

- 减小周期滤波窗口。
- 增大 IIR alpha。

### 12.4 自动停泵

宏：

```c
#define PUMP_AUTO_STOP_TIMEOUT_MS 30000U
```

如果任务可能长时间吸持，应适当增大；如果担心气泵长时间堵转或发热，应保留 30s 或更短保护。

## 13. 常见问题排查

### 13.1 PE5 没有 PWM

检查：

- `CN_Pump_TIM_init()` 是否被 `CN_Pump_init()` 调用。
- TIM15 CH1 是否配置为 PWM。
- PE5 GPIO 复用是否正确。
- `CN_Pump_Start()` 是否执行。
- `PUMP_DEFAULT_DUTY` 是否为 0。

### 13.2 PE6 频率一直为 0

检查：

- 气泵是否已经开启。当前只有 `Pump_on=1` 时才测频。
- PE6 是否接到反馈信号。
- TIM15 CH2 输入捕获中断是否开启。
- `HAL_TIM_IC_CaptureCallback()` 是否进入。
- 反馈信号是否有上升沿。

### 13.3 吸上后没有事件

检查：

- `Pump_Handle.IfSucked` 是否变为 1。
- `g_pump_state` 是否处于 `NANO_PUMP_SUCKING`。
- `Nano_COM_Task_Loop()` 是否持续运行。
- 是否因为 30s 自动停泵触发了 timeout stop。

### 13.4 停泵后工件仍吸住

停泵只是不再抽气，吸盘和管路内部仍可能保持负压。解决方式通常不是软件停泵，而是硬件上增加泄压通道，例如电磁阀、常开泄压孔或反吹结构。当前软件 release 只是关闭气泵并等待固定时间，不能主动破坏负压。
