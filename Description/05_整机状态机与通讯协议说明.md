# 整机状态机与通讯协议说明

## 1. 模块定位

整机状态机和统一通信协议主要位于：

- `Code/ChaseNum1_NanoProtocol.c`
- `Code/ChaseNum1_NanoProtocol.h`
- `Code/ChaseNum1_COM.c`
- `Code/ChaseNum1_COM.h`
- `Code/ChaseNum1_Uart.c`
- `Code/ChaseNum1_Uart.h`
- `NANO_Control/controller.py`
- `NANO_Control/communication.yml`
- `NANO_Control/nano_protocol_ui.py`

设计目标：

1. 上位机通过一套统一二进制帧控制底盘、机械臂、气泵、射击模块和系统状态。
2. 下位机启动后自动初始化，不等待上位机握手。
3. 上位机发送 HELLO 只用于确认通信链路。
4. 系统、底盘、机械臂、气泵、射击模块都有独立状态，同时由系统总状态汇总。
5. 所有回包使用帧格式，便于上位机解析。
6. 文本 printf 不作为协议内容，调试信息不应影响协议解析。

## 2. 串口选择

当前 NANO 协议串口由 `Code/ChaseNum1_COM.h` 中宏决定：

```c
#define NANO_PROTOCOL_UART2       2
#define NANO_PROTOCOL_UART7       7
#define NANO_PROTOCOL_UART_SELECT NANO_PROTOCOL_UART7
```

映射端口：

```c
#if NANO_PROTOCOL_UART_SELECT == NANO_PROTOCOL_UART2
#define NANO_PROTOCOL_UART_PORT CN_UART_2
#elif NANO_PROTOCOL_UART_SELECT == NANO_PROTOCOL_UART7
#define NANO_PROTOCOL_UART_PORT CN_UART_7
#endif
```

这保证收包和回包使用同一个串口：

- RX 回调在 `ChaseNum1_COM.c` 中根据宏转发到 `Nano_COM_RX_Callback()`。
- TX 发送在 `Nano_COM_Send_Frame()` 中使用 `NANO_PROTOCOL_UART_PORT`。

当前代码默认是 UART7。若要改为 UART2，只需要修改 `NANO_PROTOCOL_UART_SELECT`，收包和回包会一起切换到同一个串口。

串口参数：

```text
115200 baud
8 data bits
No parity
1 stop bit
No hardware flow control
```

## 3. 下位机启动流程

`USER/main.c` 上电后初始化顺序：

1. 开启 cache 和 HAL。
2. 初始化系统时钟和 delay。
3. 初始化电机 PWM 并立刻停止输出。
4. 初始化 PIT3，用于系统短延时。
5. 初始化 Debug 串口。
6. `Main_COM_init()` 初始化 NANO 通信。
7. 初始化编码器。
8. 初始化底盘运动模块。
9. 初始化机械臂。
10. 初始化 IMU。
11. 初始化气泵。
12. 初始化射击模块，关闭摩擦轮并让推弹舵机回初始位置。
13. 初始化 TFT 菜单。
14. 启动 PIT1/PIT2。
15. 调用 `Nano_COM_Notify_Init_Done()`。

`Nano_COM_Notify_Init_Done()` 会：

1. 将系统状态从 `INIT` 切到 `IDLE`。
2. 主动发送 `SYS_READY` 事件。
3. 主动发送一次 `STATUS`。

因此上位机打开串口后，可能先收到下位机主动发出的 ready/status 帧。

## 4. 主循环与周期任务

主循环只调用：

```c
Nano_COM_Task_Loop();
```

该函数内部顺序：

1. 增加主循环诊断计数。
2. 从软件环形缓冲解析接收字节。
3. 如果有完整包，处理一包命令。
4. 调用 `Arm_Task_Loop()` 推进机械臂规划。
5. 调用 `CN_Pump_Task_Loop()` 推进气泵测频和吸附判断。
6. 调用 `Shooter_Task_Loop()` 推进射击动作。
7. 更新底盘、机械臂、气泵、射击模块和系统状态。

1ms Tick 由 `CN_PIT2_CALLBACK()` 调用：

```c
Nano_COM_1ms_Tick();
```

用于协议超时计数，例如底盘 run 命令 500ms 超时、气泵 release 等待计时。

底盘闭环由 `CN_PIT1_CALLBACK()` 独立每 1ms 调用：

```c
CN_Movement_ctrl_CALLBACK(1);
```

## 5. 接收缓冲和解析

UART 接收中断每收到 1 字节调用：

```c
Nano_COM_RX_Callback(dat);
```

该函数只做一件事：把字节写入 NANO 软件环形缓冲区。真正解析帧在主循环里完成。

相关宏：

```c
#define NANO_RX_RING_SIZE    512U
#define NANO_RX_PARSE_BUDGET 64U
```

`NANO_RX_RING_SIZE` 必须是 2 的整数次幂，因为环形缓冲下标使用：

```c
index = (index + 1U) & (NANO_RX_RING_SIZE - 1U);
```

这个写法等价于对缓冲长度取模，但只在长度为 2 的幂时成立。

每次主循环最多解析 64 个字节，避免协议解析长时间占用主循环。

## 6. 帧格式

所有上位机命令和下位机回包统一格式：

```text
HEAD1 HEAD2 VER SEQ MODULE CMD LEN PAYLOAD CHECK TAIL1 TAIL2
```

字段说明：

| 字段 | 长度 | 当前值/说明 |
| --- | --- | --- |
| `HEAD1` | 1 | `0xAA` |
| `HEAD2` | 1 | `0x55` |
| `VER` | 1 | 当前 `0x01` |
| `SEQ` | 1 | 序号，上位机递增，下位机回包携带同序号 |
| `MODULE` | 1 | 模块 ID |
| `CMD` | 1 | 命令字或响应字 |
| `LEN` | 1 | payload 字节数 |
| `PAYLOAD` | N | 载荷 |
| `CHECK` | 1 | 校验和 |
| `TAIL1` | 1 | `0x0D` |
| `TAIL2` | 1 | `0x0A` |

校验和：

```text
CHECK = (VER + SEQ + MODULE + CMD + LEN + sum(PAYLOAD)) & 0xFF
```

所有 `float` 使用 IEEE754 小端格式，也就是 Python `struct.pack("<f", value)`。

## 10. 系统状态机

系统状态：

| 状态 | 值 | 含义 |
| --- | --- | --- |
| `SYS_INIT` | 0 | 初始化中 |
| `SYS_RET` | 1 | reset 复位流程中 |
| `SYS_IDLE` | 2 | 空闲 |
| `SYS_ACTIVE` | 3 | 至少一个模块正在执行 |
| `SYS_ESTOP` | 4 | 急停锁止 |
| `SYS_FAULT` | 5 | 故障预留 |

命令许可逻辑在：

```c
Nano_COM_System_Allows_Command()
```

中实现。

规则：

- `SYS_INIT`：只允许 `HELLO` 和 `GET_STATUS`。
- `SYS_RET`：只允许 `HELLO` 和 `GET_STATUS`。
- `SYS_ESTOP` 或 `SYS_FAULT`：只允许 `HELLO`、`GET_STATUS`、`RESET`。
- 其他状态：允许普通命令。

急停后必须 reset 才能恢复普通控制。

系统状态由：

```c
Nano_COM_Update_System_State()
```

汇总。如果底盘 run/rotate/translate、机械臂 moving/folding、气泵 sucking/releasing、射击 spinup/pushing/returning/resetting 任意一个活跃，系统为 `ACTIVE`，否则为 `IDLE`。

## 11. 系统命令

| 命令 | CMD | 载荷 | 回包 |
| --- | --- | --- | --- |
| `HELLO` | `0x01` | 无 | `ACK` + `STATUS` |
| `RESET` | `0x02` | 无 | `ACK`，完成后 `EVENT SYS_RESET_DONE` + `STATUS` |
| `ESTOP` | `0x03` | 无 | `ACK` + `EVENT SYS_ESTOP` |
| `GET_STATUS` | `0x04` | 无 | `STATUS` |

### 11.1 RESET 流程

`Nano_COM_Start_Reset()` 执行：

1. 系统状态置 `SYS_RET`。
2. 底盘调用 `CN_Intr_Movement()` 放松控制，协议底盘状态置 `IDLE`。
3. 机械臂发送内部 `ARM_HOST_CMD_FOLD`，回默认休息姿态。
4. 气泵停止，并进入 releasing 等待。
5. 射击模块关闭摩擦轮，并让推弹舵机回初始位置。
6. 等机械臂、气泵和射击模块都完成后，系统状态回 `SYS_IDLE`。
7. 发送 `EVENT_SYS_RESET_DONE` 和 `STATUS`。

### 11.2 ESTOP 流程

急停命令执行：

1. 底盘进入 `Movement_Breaking`。
2. 机械臂收到 STOP 并锁持。
3. 气泵停止。
4. 射击模块关闭摩擦轮，并让推弹舵机回初始位置。
5. 系统状态置 `SYS_ESTOP`。
6. 回 ACK 和 `EVENT_SYS_ESTOP`。

急停不是普通停止，后续必须 reset。

## 12. 底盘协议

底盘状态：

| 状态 | 值 |
| --- | --- |
| `IDLE` | 0 |
| `RUN` | 1 |
| `ROTATE` | 2 |
| `TRANSLATE` | 3 |
| `STOP` | 4 |
| `BRAKE` | 5 |
| `FAULT` | 6 |

### 12.1 RUN

```text
MODULE = 0x02
CMD    = 0x10
LEN    = 12
PAYLOAD = <float vx, float vy, float wz>
```

上位机范围：

- `vx`：-100~100。
- `vy`：-100~100。
- `wz`：-100~100。

映射：

| 变量 | 下位机内部范围 | 说明 |
| --- | --- | --- |
| `vx/vy` | -20~-1、0、1~20 | 非零最小输出克服死区 |
| `wz` | -200~200 | 作为 `YAW_acc` 累加航向目标 |

RUN 命令必须周期发送。超过：

```c
#define NANO_CHASSIS_RUN_TIMEOUT_MS 500U
```

未收到新 RUN，自动普通停止，并发送：

```text
EVENT_CHASSIS_TIMEOUT_STOP = 0x12
```

### 12.2 STOP

```text
MODULE = 0x02
CMD    = 0x11
LEN    = 0
```

动作：进入 run 零速度姿态保持。它不会放松电机控制。

### 12.3 BRAKE

```text
MODULE = 0x02
CMD    = 0x12
LEN    = 0
```

动作：进入底盘刹停流程，先零速度闭环抱死，确认静止或超时后放松控制。

### 12.4 ROTATE_TO

```text
MODULE = 0x02
CMD    = 0x13
LEN    = 8
PAYLOAD = <float angle_deg, float max_wz>
```

上位机：

- `angle_deg` 任意，表示相对当前姿态旋转角度。
- `max_wz` 1~100。

映射：

```text
max_wz 1~100 -> 下位机 1~10
```

如果底盘正在 rotate 或 translate，会回 `NACK BUSY`。

到位后发送：

```text
EVENT_CHASSIS_ROTATE_DONE = 0x10
```

### 12.5 TRANSLATE_REL

```text
MODULE = 0x02
CMD    = 0x14
LEN    = 12
PAYLOAD = <float dx_cm, float dy_cm, float speed>
```

上位机：

- `dx_cm`：-1000~1000。
- `dy_cm`：-1000~1000。
- `speed`：1~100。

映射：

```text
dx/dy -1000~1000 cm -> 下位机 -50000~50000
speed 1~100 -> 下位机 1~20
```

如果底盘正在 rotate 或 translate，会回 `NACK BUSY`。

到位后发送：

```text
EVENT_CHASSIS_TRANS_DONE = 0x11
```

### 12.6 GET_STATE

```text
MODULE = 0x02
CMD    = 0x15
LEN    = 0
```

返回 `CHASSIS_STATE`。

## 13. 机械臂协议

机械臂状态：

| 状态 | 值 |
| --- | --- |
| `IDLE` | 0 |
| `MOVING` | 1 |
| `FOLDING` | 2 |
| `HOLD` | 3 |
| `REJECTED` | 4 |
| `FAULT` | 5 |

### 13.1 TARGET_XYZ_DIR

```text
MODULE = 0x03
CMD    = 0x20
LEN    = 16
PAYLOAD = <float x_cm, float y_cm, float z_cm, float dir_deg>
```

含义：

- `x/y/z`：吸盘末端世界坐标，单位 cm。
- `dir_deg`：吸盘在目标竖直平面内方向，`0°` 竖直向下，`90°` 水平向外，`180°` 竖直向上。

如果机械臂正在 moving/folding，或者内部规划器忙，会回 `NACK BUSY`。

命令接受后先回 ACK，动作完成后回：

```text
EVENT_ARM_DONE = 0x20
```

不可达、进禁区或限位失败则回：

```text
EVENT_ARM_REJECTED = 0x22
```

### 13.2 FOLD_HOME

```text
MODULE = 0x03
CMD    = 0x21
LEN    = 0
```

当前语义是回默认休息姿态，不是停在折叠过渡姿态。完成后：

```text
EVENT_ARM_FOLD_DONE = 0x21
```

### 13.3 STOP_HOLD

```text
MODULE = 0x03
CMD    = 0x22
LEN    = 0
```

动作：停止当前规划并锁持舵机。命令接受后回 ACK。当前 STOPPED 内部事件只更新协议状态为 HOLD，不额外发送独立事件。

### 13.4 GET_POSE

```text
MODULE = 0x03
CMD    = 0x23
LEN    = 0
```

返回 `ARM_POSE`。当前返回逻辑位姿，不是舵机真实反馈位姿。

### 14.1 SUCK

```text
MODULE = 0x04
```

```text
EVENT_PUMP_RELEASE_DONE = 0x31
```

### 14.3 GET_STATE

```text
MODULE = 0x04
CMD    = 0x32
LEN    = 0
```

返回 `PUMP_STATE`。

### 15.1 FIRE

```text
MODULE = 0x05
CMD    = 0x40
LEN    = 0
```

动作：摩擦轮先启动预热，然后 UART5 推弹舵机运动到推弹位置，随后关闭摩擦轮，舵机回初始位置。

完成后发送：

```text
EVENT_SHOOTER_DONE = 0x40
```

若超过 `SHOOTER_ACTION_TIMEOUT_MS`，会强制关闭摩擦轮并发送：

```text
EVENT_SHOOTER_TIMEOUT = 0x42
```

### 15.2 RESET

```text
MODULE = 0x05
CMD    = 0x41
LEN    = 0
```

动作：立即关闭摩擦轮，并让推弹舵机回初始位置。完成后发送：

```text
EVENT_SHOOTER_RESET_DONE = 0x41
```

### 15.3 GET_STATE

```text
MODULE = 0x05
CMD    = 0x42
```

## 16. 回包载荷格式

### 16.1 ACK/NACK

格式：

```text
<uint8 source_seq, uint8 source_module, uint8 source_cmd, uint8 err, uint8 state>
```

说明：

- `source_seq`：对应上位机原命令序号。
- `source_module`：原命令模块。
- `source_cmd`：原命令字。
- `err`：错误码，ACK 为 0。
- `state`：当前模块或系统状态。

### 16.2 EVENT

格式：

```text
<uint8 source_seq, uint8 module, uint8 event, uint8 state, uint8 result>
```

说明：

- `source_seq`：触发该事件的上位机命令序号。
- `module`：事件所属模块。
- `event`：事件码。
- `state`：事件发生后的模块状态。
- `result`：结果码，通常是 `OK` 或 `TIMEOUT/RANGE_LIMIT`。

事件码：

| 事件 | 值 |
| --- | --- |
| `SYS_READY` | `0x01` |
| `SYS_RESET_DONE` | `0x02` |
| `SYS_ESTOP` | `0x03` |
| `CHASSIS_ROTATE_DONE` | `0x10` |
| `CHASSIS_TRANS_DONE` | `0x11` |
| `CHASSIS_TIMEOUT_STOP` | `0x12` |
| `ARM_DONE` | `0x20` |
| `ARM_FOLD_DONE` | `0x21` |
| `ARM_REJECTED` | `0x22` |
| `PUMP_SUCK_DONE` | `0x30` |
| `PUMP_RELEASE_DONE` | `0x31` |
| `PUMP_TIMEOUT_STOP` | `0x32` |
| `SHOOTER_DONE` | `0x40` |
| `SHOOTER_RESET_DONE` | `0x41` |
| `SHOOTER_TIMEOUT` | `0x42` |

### 16.3 STATUS

格式：

```text
<BBBBBBBBIfB>
```

字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `system_state` | u8 | 系统状态 |
| `chassis_state` | u8 | 底盘协议状态 |
| `arm_state` | u8 | 机械臂协议状态 |
| `pump_state` | u8 | 气泵协议状态 |
| `movement_type` | u8 | 底层底盘运动模式 |
| `pump_on` | u8 | 气泵是否开启 |
| `if_sucked` | u8 | 是否吸附 |
| `arm_planner_active` | u8 | 机械臂规划器是否忙 |
| `ms_tick` | u32 | 协议毫秒计数 |
| `yaw_deg` | float | 当前 IMU yaw |
| `shooter_state` | u8 | 射击模块协议状态 |

### 16.4 CHASSIS_STATE

格式：

```text
<BBfffff>
```

字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `chassis_state` | u8 | 底盘协议状态 |
| `movement_type` | u8 | 底层运动模式 |
| `yaw_deg` | float | 当前 yaw |
| `vx` | float | 上位机量程下的 vx 回显 |
| `vy` | float | 上位机量程下的 vy 回显 |
| `wz` | float | 上位机量程下的 wz 回显 |
| `distance_cm` | float | 平移剩余距离换算到上位机 cm 量程后的值 |

### 16.5 ARM_POSE

格式：

```text
<BBBBffffffff>
```

字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `arm_state` | u8 | 机械臂协议状态 |
| `pose_source` | u8 | 预留，当前为 0 |

## 20. 调试注意事项

### 20.1 为什么上位机可能要发两次才执行

历史上 UART2 开过硬件 FIFO，而代码使用 1 字节中断接收，可能出现尾字节滞留或接收触发不及时。当前 UART2 已关闭硬件 FIFO：

```c
UART2_Handle.Init.FIFOMode = UART_FIFOMODE_DISABLE;
```

同时 RX 字节先进软件环形缓冲，主循环解析完整帧。

### 20.2 为什么高频发送会卡

可能原因：

- 上位机发包频率过高，软件环形缓冲堆积。
- 上一包还没处理完，新完整帧到达导致 `rx_busy_drop_count` 增加。
- UART overrun。
- TX 回包太多，发送 FIFO 堵塞。
- 主循环被其他耗时任务阻塞。

可通过 TFT 菜单中的 `UART2 RX`、`Frames`、`Buffer`、`Link`、`Errors` 判断。

### 20.3 文本输出会不会影响协议

统一协议本身只解析符合 `AA 55 ... 0D 0A` 的二进制帧。如果同一个串口混入 printf 文本，上位机 controller 可以显示原始文本，但协议解析会跳过无法成帧的数据。

工程设计上仍建议 NANO 协议串口不要混入大量文本，否则会占用带宽，也可能增加解析负担。

## 21. 后续扩展建议

1. 新增外设时，优先新增 module ID 或在现有模块下新增 cmd，保持帧格式不变。
2. 每个新动作都应区分“ACK 已接收”和“EVENT 已完成”。
3. 长时间动作必须有超时或可停止命令。
4. 状态查询回包应固定长度，便于 Python `struct.unpack`。
5. 如果增加故障检测，应让 `SYS_FAULT` 和各模块 `FAULT` 真正参与命令许可，而不是只作为预留状态。
