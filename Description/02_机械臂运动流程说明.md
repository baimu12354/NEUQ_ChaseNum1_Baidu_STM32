# 机械臂运动流程说明

## 1. 模块定位

机械臂相关代码主要位于：

- `Code/ChaseNum1_MecArm.c`
- `Code/ChaseNum1_MecArm.h`
- `Code/ChaseNum1_BusServo.c`
- `Code/ChaseNum1_BusServo.h`
- `Code/ChaseNum1_NanoProtocol.c`

机械臂模块自身负责：

1. 接收内部命令邮箱 `g_HostCmd`。
2. 根据吸盘末端空间坐标和吸盘方向进行逆运动学求解。
3. 检查禁区、前方细杆和舵机物理限位。
4. 根据是否跨过世界坐标 `x=0` 决定是否插入折叠过渡姿态。
5. 分阶段向总线舵机发送目标角度。
6. 生成内部事件，供统一协议状态机回包。

机械臂模块不再直接解析上位机串口文本，也不直接向上位机 printf 回包。当前所有对上位机的 ACK、事件、位姿回包都由 `ChaseNum1_NanoProtocol.c` 统一负责。

## 2. 坐标系定义

当前上位机发送的是吸盘末端的三维空间坐标和吸盘在竖直平面内的朝向：

- `world_x`：水平面内 X 坐标，单位 cm。
- `world_y`：水平面内 Y 坐标，单位 cm。
- `world_z`：竖直高度，单位 cm。
- `suc_dir_deg`：吸盘在目标竖直平面内的绝对朝向，单位 deg。

坐标约定：

- 原点是云台中心在地面上的投影。
- 云台虚拟 `0°` 指向水平面内 `+Y`。
- 云台虚拟 `90°` 指向水平面内 `+X`。
- `+Z` 为竖直向上。

云台角由：

```c
atan2f(world_x, world_y)
```

计算，这和普通数学中 `atan2(y,x)` 不同，是为了满足 `0° -> +Y`、`90° -> +X` 的工程定义。

## 3. 几何参数

机械臂几何参数定义在 `ChaseNum1_MecArm.c` 文件开头：

| 宏 | 当前值 | 单位 | 含义 |
| --- | --- | --- | --- |
| `ARM_H0` | 11.8 | cm | 云台中心距地面高度 |
| `ARM_H1` | 6.1 | cm | 云台中心到大齿轮关节的高度差 |
| `ARM_R` | 3.1 | cm | 云台中心到大齿轮关节的水平投影偏置 |
| `ARM_L1` | 17.5 | cm | 第一段机械臂名义长度 |
| `ARM_C` | 2.0 | cm | 第二关节相对第一段机械臂的垂直机械偏置 |
| `ARM_L2` | 21.0 | cm | 第二段机械臂长度 |
| `ARM_L3` | 9.0 | cm | 第四舵机轴心到吸盘末端距离 |

逆解和上位机可视化都依赖这些参数。若下位机修改了机械臂结构参数，上位机 UI 中的同名参数也应同步，否则三维显示会和真实运动不一致。

## 4. 舵机和虚拟角

机械臂用 4 个总线舵机：

| 逻辑轴 | 舵机 ID | 含义 |
| --- | --- | --- |
| `th0` | `S0_ID = 0` | 云台旋转轴 |
| `th1` | `S1_ID = 1` | 第一主臂轴，多圈模式 |
| `th2` | `S2_ID = 2` | 第二主臂轴 |
| `th3` | `S3_ID = 3` | 吸盘末端方向补偿轴 |

虚拟角到物理角映射由 `Arm_Map_To_Servo_Angles()` 完成：

```c
actual_s0 = th0 * S0_GEAR * S0_DIR + S0_OFFSET;
actual_s1 = th1 * S1_GEAR * S1_DIR + S1_OFFSET;
actual_s2 = th2 * S2_GEAR * S2_DIR + S2_OFFSET;
actual_s3 = th3 * S3_GEAR * S3_DIR + S3_OFFSET;
```

当前标定值：

| 舵机 | `GEAR` | `DIR` | `OFFSET` | 物理范围 |
| --- | --- | --- | --- | --- |
| S0 | 1.0 | 1.0 | 2.0 | -180~180 deg |
| S1 | 3.0 | 1.0 | -520.0 | -520~20 deg |
| S2 | 1.0 | -1.0 | -13.0 | -90~150 deg |
| S3 | 1.0 | -1.0 | -95.0 | -190~10 deg |

注意 S1 是多圈舵机，`S1_GEAR = 3.0` 表示虚拟角变化会放大为物理多圈角变化。修改 `th1` 相关姿态时，必须同时考虑物理角是否越过 `S1_MIN/S1_MAX`。

## 5. 吸盘方向定义

在平面逆解 `Arm_Plane_Inverse_Kinematics()` 中，吸盘方向被转换成平面内向量：

```c
suc_dx = sin(dir);
suc_dz = -cos(dir);
```

因此：

- `dir = 0°`：吸盘竖直向下。
- `dir = 90°`：吸盘沿平面深度正方向水平伸出。
- `dir = 180°`：吸盘竖直向上。

末端舵机角由：

```c
th3 = normalize((dir - 90) - th1 - th2);
```

得到。这里的 `dir - 90` 是把吸盘绝对方向转换到机械臂平面链条角度定义下。

## 6. 逆运动学流程

外部接口：

```c
uint8_t Arm_Inverse_Kinematics(
    float world_x,
    float world_y,
    float world_z,
    float suc_dir_deg,
    float *out_th0,
    float *out_th1,
    float *out_th2,
    float *out_th3);
```

流程如下。

### 6.1 世界坐标转云台平面

先计算云台角和目标点在当前竖直运动平面内的深度：

```c
base_th0 = atan2f(world_x, world_y);
plane_x = sqrtf(world_x * world_x + world_y * world_y);
plane_z = world_z;
```

`plane_x` 是目标点距云台中心竖直轴的水平距离，永远非负。正负侧由 `base_th0` 表示。

### 6.2 禁区检查

逆解前先调用：

```c
Arm_Target_In_Forbidden_Zone(&target)
```

如果目标落入禁区，直接返回失败，不会继续求解或下发舵机。

### 6.3 由吸盘末端反推腕部点

吸盘末端到第四舵机轴心长度是 `ARM_L3`。目标是吸盘末端，所以要先把末端沿吸盘方向往回退 `L3`，得到腕部目标：

```c
wrist_x = plane_x - ARM_L3 * suc_dx;
wrist_z = plane_z - ARM_L3 * suc_dz;
```

例如 `dir=0°` 竖直向下时，`suc_dx=0`、`suc_dz=-1`，因此：

```text
wrist_z = plane_z + ARM_L3
```

也就是第四舵机轴心在吸盘末端上方。

### 6.4 两连杆逆解

`Arm_Wrist_Inverse_Kinematics()` 求解 `th1` 和 `th2`。

由于第一段机械臂存在垂直偏置 `ARM_C`，代码先把第一段等效为：

```c
l_eff = sqrt(ARM_L1^2 + ARM_C^2)
phi = atan2(ARM_C, ARM_L1)
```

再用余弦定理判断腕部点是否在两连杆可达范围内：

```c
d > l_eff + ARM_L2      -> 太远，不可达
d < fabs(l_eff - ARM_L2)-> 太近，不可达
```

可达时，通过几何关系求出 `th1`、`th2`。

### 6.5 末端角和限位检查

得到 `th0/th1/th2/th3` 后调用：

```c
Arm_Is_Servo_Angle_In_Range()
```

把虚拟角映射为物理角，再检查每个舵机是否在范围内。若任意一个舵机越限，逆解失败。

## 7. 禁区和前方细杆

### 7.1 当前实际禁区

当前代码使用梯形禁区，宏定义为：

```c
#define ARM_FORBID_Y_NEAR_CM       3.0f
#define ARM_FORBID_Y_FAR_CM        30.0f
#define ARM_FORBID_X_HALF_NEAR_CM  9.0f
#define ARM_FORBID_X_HALF_FAR_CM   90.0f
#define ARM_FORBID_Z_MAX_CM        20.0f
```

判断条件是严格不等式：

```text
3 < y < 30
z < 20
-x_half(y) < x < x_half(y)
```

其中 `x_half(y)` 由 `Arm_Forbidden_X_Half_Width()` 线性插值：

```text
x_half(y) = near_half + (y - 3) / (30 - 3) * (far_half - near_half)
```

当前实际代码值是：

```text
y = 3  时，半宽约 9cm
y = 30 时，半宽约 90cm
```

注意：代码注释中有“对应 -5<x<5”和“对应 -50<x<50”的历史文字，但当前宏值实际是 9 和 90。工程运行以宏值为准。如果后续要恢复为用户最初提出的 `5/50cm`，应修改 `ARM_FORBID_X_HALF_NEAR_CM` 和 `ARM_FORBID_X_HALF_FAR_CM`，并同步修改上位机 UI 可视化参数。

### 7.2 前方细杆避让

前方细杆只检查吸盘最终目标点是否太靠近：

```c
#define ARM_FRONT_ROD_Y_CM      25.0f
#define ARM_FRONT_ROD_RADIUS_CM 0.5f
```

如果：

```text
abs(x) <= 0.5
abs(y - 25) <= 0.5
```

则 `Arm_Target_Too_Close_To_Front_Rod()` 返回失败。当前代码没有做复杂路径绕杆，只在目标点层面避免末端直接落到杆附近。

## 8. 折叠姿态和休息姿态

机械臂当前区分两个固定姿态：

1. 折叠过渡姿态：用于跨过世界坐标 `x=0` 时收敛机械臂，避免云台换侧时末端扫入禁区。
2. 默认休息姿态：用于机械臂不用时减小舵机受力，尤其让第三舵机连带臂尽量向下。

### 8.1 折叠过渡姿态

宏定义：

```c
#define ARM_FOLD_TH1_DEG 120.0f
#define ARM_FOLD_TH2_DEG -120.0f
#define ARM_FOLD_TH3_DEG -90.0f
```

折叠姿态由 `Arm_Build_Folded_Pose()` 生成。它会：

1. 使用传入的云台平面角 `base_th0`。
2. 固定 `th1/th2/th3`。
3. 检查物理舵机限位和安全余量。
4. 用正运动学算出该姿态下的吸盘末端坐标。
5. 检查折叠末端是否落入禁区。

折叠姿态不是默认休息姿态，只用于运动规划过程。

### 8.2 默认休息姿态

宏定义：

```c
#define ARM_DEFAULT_REST_BASE_DEG 90.0f
#define ARM_REST_TH1_DEG          80.0f
#define ARM_REST_TH2_DEG         -150.0f
#define ARM_REST_TH3_DEG           0.0f
```

休息姿态由 `Arm_Build_Rest_Pose()` 生成。上位机发送 `ARM_FOLD_HOME` 命令时，当前语义实际是“回默认休息姿态”，不是停在折叠过渡姿态。

这样设计的原因是折叠姿态虽然适合跨平面过渡，但长期停在那里舵机受力较大；休息姿态让第三舵机连带臂尽量向下，减小保持力矩。

## 9. 运动规划流程

机械臂规划器核心结构：

```c
typedef struct {
    uint8_t active;
    uint8_t plan_cmd_type;
    uint8_t phase_count;
    uint8_t phase_index;
    uint32_t phase_start_tick;
    ArmPlanPhase_t phases[ARM_PLAN_PHASE_MAX];
    ArmWorldTarget_t final_target;
    ArmJointPose_t final_pose;
} ArmMotionPlan_t;
```

最大阶段数：

```c
#define ARM_PLAN_PHASE_MAX 3U
```

三个阶段最多对应：

1. 当前平面收敛到折叠姿态。
2. 保持折叠姿态旋转云台到目标平面。
3. 从折叠姿态展开到目标姿态。

### 9.1 同侧运动

如果当前目标和新目标都在世界坐标 X 轴同一侧，或者有一方靠近 `x=0` 死区：

```c
#define ARM_X_SIDE_EPS_CM 1.0f
```

则 `Arm_Target_Crosses_X_Zero()` 返回 0，规划器只添加最终目标阶段：

```text
direct
```

这种情况下机械臂直接从当前逻辑姿态去目标姿态，不额外收敛。

### 9.2 跨过 x=0

如果当前目标点和新目标点分属 `x>1cm` 与 `x<-1cm` 两侧，则认为跨过世界坐标 `x=0`。

规划器 `Arm_Build_Motion_Plan()` 会：

1. 在当前云台平面生成折叠姿态。
2. 在目标云台平面生成折叠姿态。
3. 如果当前姿态到折叠姿态变化超过 0.5deg，添加 `fold` 阶段。
4. 如果两个折叠姿态的云台角变化超过 `ARM_PLANE_ROTATE_SKIP_DEG`，添加 `rotate` 阶段。
5. 添加最终目标 `expand` 阶段。

这样机械臂不会从一侧直接扫到另一侧，而是先收起来、换平面、再展开。

### 9.3 回默认休息姿态

`Arm_Build_Fold_Home_Plan()` 负责回休息姿态：

1. 如果当前逻辑姿态有效，先以当前姿态为起点。
2. 在当前平面生成折叠姿态。
3. 在默认休息云台角 `ARM_DEFAULT_REST_BASE_DEG` 上生成折叠姿态。
4. 生成默认休息姿态。
5. 按需要添加 `fold`、`rotate`、`rest` 阶段。

也就是说，回休息姿态同样会先收敛再旋转，不是直接把云台和各轴一起硬切。

## 10. 阶段等待时间

每个阶段的等待时间由：

```c
static uint32_t Arm_Estimate_Phase_Wait_Ms(const ArmJointPose_t *from, const ArmJointPose_t *to);
```

估算。

流程：

1. 将起点和终点虚拟角映射成物理舵机角。
2. 计算四个舵机中最大角度变化量。
3. 用速度估算运动时间：

```c
wait_ms = max_delta * 10000 / ARM_SERVO_MOVE_SPEED;
```

4. 添加额外裕度：

```c
#define ARM_PHASE_SETTLE_EXTRA_MS 500U
```

5. 限制到：

```c
#define ARM_PHASE_MIN_INTERVAL_MS 500U
#define ARM_PHASE_MAX_INTERVAL_MS 5000U
```

该等待是非阻塞的，代码通过 `HAL_GetTick()` 判断是否进入下一阶段，没有使用延时函数阻塞主循环。

## 11. 舵机下发流程

最终下发函数：

```c
static uint8_t Arm_Execute_Pose(const ArmJointPose_t *pose);
```

流程：

1. 检查姿态指针。
2. 检查虚拟角映射后是否在物理限位内。
3. 调用 `Arm_Map_To_Servo_Angles()`。
4. 调用 `Arm_Send_Servo_Targets()`。

当前宏：

```c
#define ARM_USE_SYNC_SERVO_SPEED_CMD 0
```

因此默认不使用总线同步速度指令，而是逐个舵机下发高级速度命令：

- S0：单圈速度命令。
- S1：多圈速度命令。
- S2：单圈速度命令。
- S3：单圈速度命令。

如果后续确认总线同步命令稳定，可以将 `ARM_USE_SYNC_SERVO_SPEED_CMD` 改为 1。当前保留宏开关是为了在同步命令不稳定时能快速退回逐个下发方式。

舵机速度相关宏：

```c
#define ARM_SERVO_MOVE_SPEED       1000U
#define ARM_SERVO_MOVE_SPEED_MULTI 5000U
#define ARM_SERVO_ACCEL_TIME_MS    500U
#define ARM_SERVO_DECEL_TIME_MS    500U
#define ARM_SERVO_POWER_LIMIT      10000U
```

## 12. 任务循环和事件

机械臂周期任务入口：

```c
void Arm_Task_Loop(void);
```

该函数在 `Nano_COM_Task_Loop()` 中被调用，因此依赖主循环持续运行。

处理顺序：

1. 如果收到 STOP 命令，立即停止所有舵机、清规划器、生成 `ARM_STATUS_EVENT_STOPPED`。
2. 如果收到 FOLD 命令，启动回默认休息姿态规划。
3. 调用 `Arm_Update_Plan()` 推进当前规划阶段。
4. 如果收到 MOVE 命令，构造目标并启动目标规划。

内部事件：

| 事件 | 值 | 含义 |
| --- | --- | --- |
| `ARM_STATUS_EVENT_DONE` | 1 | 目标动作完成 |
| `ARM_STATUS_EVENT_FOLD_DONE` | 2 | 回默认休息姿态完成 |
| `ARM_STATUS_EVENT_REJECTED` | 3 | 命令被拒绝，常见原因是禁区、不可达或限位 |
| `ARM_STATUS_EVENT_STOPPED` | 4 | 已停止并锁持 |

协议层通过：

```c
Arm_Fetch_Status_Event(&event)
```

读取并清除事件，然后转成 NANO 协议事件包。

## 13. 初始化

初始化入口：

```c
void Arm_Init(void);
```

当前宏：

```c
#define ARM_INIT_USE_PLANNER_HOME 0U
```

因此当前初始化默认直接执行默认休息姿态，而不是走完整规划器流程。

如果将其改为 `1U`，初始化会走 `Arm_Start_Fold_Home()`，也就是先按规划器回默认休息姿态。该模式适合机械臂上电姿态可能跨过禁区的情况，但前提是当前舵机位置读取和初始姿态假设足够可靠。

初始化时还可尝试读取云台当前角：

```c
#define ARM_INIT_READ_BASE_ENABLE 1U
#define ARM_INIT_BASE_READ_TIMEOUT_MS 50U
```

读取失败时使用：

```c
#define ARM_INIT_FALLBACK_BASE_DEG ARM_DEFAULT_REST_BASE_DEG
```

作为保守假设。

## 14. 当前位置读取

统一协议支持上位机读取机械臂逻辑位姿。底层接口：

```c
void Arm_Get_Logical_Pose(
    float *x, float *y, float *z, float *dir,
    float *th0, float *th1, float *th2, float *th3);
```

当前返回的是“逻辑位置”，即代码认为机械臂已经执行到的目标点和关节角，不一定是舵机真实反馈位置。后续如果改为真实位置，需要在舵机反馈读取稳定后替换这里的数据来源。

## 15. 上位机命令关系

机械臂协议命令在 `Nano_COM_Process_Package()` 中处理：

| 上位机命令 | CMD | 载荷 | 下位机动作 |
| --- | --- | --- | --- |
| `ARM_TARGET_XYZ_DIR` | `0x20` | `<ffff>` | 写入 `g_HostCmd`，启动目标规划 |
| `ARM_FOLD_HOME` | `0x21` | 无 | 回默认休息姿态 |
| `ARM_STOP_HOLD` | `0x22` | 无 | 停止当前规划并锁持 |
| `ARM_GET_POSE` | `0x23` | 无 | 返回逻辑位姿 |

收到目标命令后先回 ACK，真正到位后再由 `Arm_Fetch_Status_Event()` 触发：

```text
EVENT_ARM_DONE = 0x20
```

回默认休息姿态完成：

```text
EVENT_ARM_FOLD_DONE = 0x21
```

不可达、禁区或限位失败：

```text
EVENT_ARM_REJECTED = 0x22
```

## 16. 常见问题排查

### 16.1 目标无法到达

优先检查：

1. 是否落入梯形禁区。
2. 是否太靠近前方细杆。
3. `ARM_L1/L2/L3/H0/H1/R/C` 是否和实物一致。
4. `suc_dir_deg` 是否设置为期望方向，尤其竖直向下应为 `0°`。
5. 虚拟角映射后的物理角是否超出 `Sx_MIN/Sx_MAX`。

### 16.2 云台或大臂越位

优先检查：

- `S0_OFFSET/S1_OFFSET` 是否和标定一致。
- `ARM_DEFAULT_REST_BASE_DEG` 和初始实物摆放是否一致。
- 是否把 `ARM_INIT_USE_PLANNER_HOME` 打开后，初始逻辑起点和真实起点差别过大。
- S1 多圈物理角是否被 `S1_GEAR` 放大后越过范围。

### 16.3 跨 x=0 时扫入禁区

检查：

- `g_arm_current_valid` 是否已经有效。如果逻辑当前位置无效，规划器只能从目标或默认假设出发。
- 之前是否在机械臂还未到上一段目标时又发送新目标。当前起点是逻辑状态，不是真实读取状态，连续抢发命令可能导致规划起点不准。
- `ARM_PHASE_SETTLE_EXTRA_MS` 是否太小，导致上一阶段还没完全到位就进入下一阶段。

### 16.4 上位机 UI 禁区显示和下位机不一致

当前 `NANO_Control/nano_protocol_ui.py` 中也有机械臂几何和禁区参数。若下位机宏变化，必须同步 UI，否则可视化只作为参考，不能代表下位机真实判定。

## 17. 后续维护建议

1. 新增机械臂结构参数时，优先在 `ChaseNum1_MecArm.c` 开头宏定义集中维护。
2. 修改任何固定姿态后，必须检查：
   - 正运动学末端是否落入禁区。
   - 舵机物理角是否留足安全余量。
   - S1 多圈角是否接近极限。
3. 如果总线同步命令实测不稳定，保持 `ARM_USE_SYNC_SERVO_SPEED_CMD = 0`。
4. 如果要提高连续命令响应，建议先做真实舵机位置读取，再用真实位置作为新规划起点。
