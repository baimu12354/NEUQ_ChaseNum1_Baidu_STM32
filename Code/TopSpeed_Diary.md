    第一版差不多就到这了，或者应该在4.10左右的某次提交处；
    19届的XZ轴大云台+步进电机驱动的方案，已经能够完成第一个夹圆柱体的任务了；
    这版方案的使命已经结束了：作为赛题发布前对上下位机通信、配合的磨合以及对机械队员的训练；
    新赛题发布后，这一版方案已经无法满足所有任务了，在简单测试机械臂的性能后，我们决定全力投入机械臂的方案：
    用一个大六轴机械臂解决90%的动作需求，包括巡线、夹取物品、存放物品、击倒目标、弹弓瞄准、弹弓装填等等；
    弹弓的方案也已经基本成型：使用越野的六步换相BLDC电机直驱同步带，完成沙包的弹射；
    这个方案的优势在于：节约电机，在12个电机限制、底盘用掉四个、机械臂用掉六个的情况下，弹射装置整个只使用一个电机，留出电机数量的冗余；射程充裕：根据理论计算，将沙包在最佳弹射角下弹射到两米外需要末端速度约3-5m/s(取决于是否考虑风阻、弹射台末端高度)，在5m/s的末端速度、30cm加速行程下，弹射装置的线加速度会达到4-5G，角速度达到3000rpm(同步带轮1cm半径下)，这些要求直接否定了普通有刷电机(转速、转矩、响应速度不足)、FOC云台/关节电机(转速通常不快)、闭环步进电机(转速比较极限)；正好越野那边使用的大红电机扭矩、转速都远远超过需要，故选择此方案；
    同时被pass掉的方案还有弹簧动力+齿条锁止发射或弹簧动力+步进电机+蜗轮蜗杆等等方案，大多是因为过于复杂，而且无一例外使用了两个以上电机数量；

    到这里之后的功能不再兼容ZX大云台方案了；
    接下来会逐步替换动作机构的驱动和通信接口；
    会在这一版迭代重构上下位机通信，暂定使用JSON传输指令；

## 第二版

_25.5.18_{
    测试自制的机械臂后，效果非常差，主要是舵机作为关节电机的输出扭矩和控制精度完全达不到要求；
    所以回退到4.10左右的进度，并重新启用XZ轴云台+吸盘的官模方案；
    这部分决策失误有几个原因：
        1.对机械臂方案没有严谨验证可行性，没有测试重载舵机实际能够稳定输出的扭矩，没有计算自制的机械臂需要多大的关节扭矩，
            甚至制作完后都不知道机械臂有多重，测试完后才发祥舵机远远达不到驱动这么庞大的机械臂的性能；最开始决定全力投入
            机械臂方案仅仅只是简单测试了商品的、轻载、总线舵机小机械臂，能够完成基本的运动学逆解和操作，就认为机械臂方案
            能满足要求，能做出来，实际上是低估了任务难度、高估了团队的水平，最终也证明，完全有比机械臂更可靠的、更稳定、
            也更简单的方案；
        2.对官模前期流出的方案过于轻视，早期流出的照片已经可以确认官模采用大云台+吸盘的方案，但是下意识地认为官模方案粗糙、
            认为气泵吸盘不够可靠，没有严谨地考证、没有测试就直接略过了官模方案。其实如果买一个气泵和吸盘试一下就能得到理想
            的效果，结果直到官模的任务视频发出才相信吸盘方案足够可靠；
        3.并没有将完成比赛任务作为第一目标，设计方案时过于理想浪漫，妄图通过“一个大机械臂解决所有问题”。但实际上那时候就
            清楚这并不是最经济、最可靠的方案。

    为云台方案重新设计引脚；
}

_25.5.21_{
    测试弹弓，效果极差，再次废弃方案；
    改用官模的电磁铁+弹簧方案；

    这个决策失误也是类似的原因：
        1.没有严格验证可行性，仅仅数值计算了几个参数，并没有验证，甚至只要让电机空载加速就能发现不管是步进还是BLDC都没法在
            这么短的距离内达到目标的速度；
        2.还是过于理想浪漫，其实一开始就清楚弹簧是最稳定的方案，因为电机直驱弹射依赖电机的动态响应，必须从目标速度曲线下方
            接近目标速度(弹射只有推力没有拉力，只能加速不能减速)；又由于加速距离很短，就要求响应曲线必须很陡峭，但又不能
            超调，这实际上非常难；对于BLDC而言，可能整个行程几十个霍尔信号就结束了，完全不足以充分响应；
}
